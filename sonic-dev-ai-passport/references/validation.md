# 环境、构建、诊断与实机交接

## 环境

先核验 OS/架构/shell、本地或 WSL/容器、现有工具链是否仅未激活。优先激活已安装 ESP-IDF 5.5.3，确认 `idf.py --version` 后配置；不替换其他安装，不输出完整环境或认证配置。原生 Windows 使用上游文档的 IDF 环境，Bash 门禁另需兼容 shell；WSL 可构建不代表能访问 USB。

安装按 engineering/environment-setup.md 对应平台路径，保留代理、工具、sdkconfig 和分区。不得禁用 TLS/安全保护、删除缓存或改全局 shell/Git 来绕过问题。失败后根据新证据修复，不无限重试；诊断环境的请求不隐含安装或改配置授权。构建就绪和设备可达分别报告。

## 构建归档

在目标源码运行 `./tools/validate.sh` 完整门禁。迭代可用 `--static` 或 `--firmware`；仅构建请求使用后者时报告省略主机测试。隔离门禁从 sdkconfig.defaults 配置，不是 ignored sdkconfig；必须确认用户本地配置与交付变体一致。允许有效自定义分区，但验证 8MB 边界、偏移/重叠/MD5、镜像大小和资源合并。

输出为 `build/FoloToy-AI-Passport-full.bin` 与 `build/firmware/<full-bin-sha256>/`，运行 `python3 tools/archive_firmware.py verify <archive-directory>`。以 manifest 绑定 full.bin、匹配 ELF/MAP、app、bootloader、分区表和 flash_args；额外自定义分区不一定有单独镜像，分段刷写前补齐。相同内容归档按上游约定复用首次 MAP，不拿后续重建 ELF 替代 dirty 固件符号。

交付从 0x0 刷写的 full.bin，绝不把 app-only 放到 0x0。记录 SHA-256、源提交/分支/dirty、配置/依赖/工具链；dirty 源码保存可恢复补丁和新增文件（先检查敏感内容，仅本地归档）。失败构建遗留旧镜像不是本轮产物。归档不等于硬件验收或厂商信任证明，不自动发布含嵌入秘密的固件/调试文件。

## 实机授权与测试

只读枚举端口，如 `python -m serial.tools.list_ports -v`，不打开/复位任意设备，不默认首个端口。无设备提示开机和数据线；环境无法访问本机 USB 则说明权限/环境限制，不能声称物理设备未连接。

绑定具体设备端口、已校验镜像及数据需求，取得本次刷写授权后执行。已有明确覆盖这些事实的本次授权不重复问；旧版本授权/构建/连接不是本次同意。合并镜像填充可能覆盖 NVS/PHY；需保留设置时核验分区兼容和匹配分段镜像，不盲刷 full.bin。全片擦除另行确认，不强制原厂备份；不能通过 rebuild-and-flash 换掉已确认镜像，flash_args 当数据而非 shell 执行。

刷写失败检查线缆、端口占用、权限/启动模式，仅在相关修正后有限重试，不杀无关进程或擅自擦除。刷后有界采集启动日志，说明串口监视是否复位；使用匹配 ELF，记录图像身份、动作和现象，结束关闭监视释放端口。

实际验证启动、新 UI 导航、三键、中文/标点/弹窗、切页任务、断电和异常恢复；按功能增加网络/音频/电池/功耗。验证热点设备后缀稳定。首次初始化时验证热点和本地 Web 配置页的初始默认值 `12345678`，已有配置时验证原凭据仍然生效。记录结果时省略实际密码。日志清洁或烧录成功不证明显示、声音、射频或续航。

报告分别列 Build、Host tests、Device tests（PASS/FAIL/NOT RUN）和 Unverified。拒绝/无法实测标 NOT RUN，保留待验清单。

## 运行时故障诊断

先区分诊断和修复请求，日志不一定来自当前 checkout。收集症状、重现动作、首个相关错误、复位类型、任务、版本和 ELF SHA；不索要秘密/整份环境。区分观察、推断、待验假设：栈指针越界可证明栈故障，但具体分配/调用位置需要匹配符号。

用 verify 检查归档并比对 manifest 的 app_elf_sha256；短 hash 必须唯一匹配。只有匹配后用 `riscv32-esp-elf-addr2line -pfiaC -e <matching.elf> <addresses>` 解码 PC 和可信栈帧，原始栈字不是全为返回地址。无符号仅报告日志能证明之事，不重建当前源码冒充旧 ELF。

按证据检查栈/局部缓冲、分配失败/最大连续堆、UI 线程/字体、外设初始化及退出后回调。不得禁用 watchdog/栈保护、隐藏缺字或无预算地增大所有栈。仅诊断时新探针/重编译/实验是建议；获修复任务后做最小有依据更改、回归检查和正常交付。
