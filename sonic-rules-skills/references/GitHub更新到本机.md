# 从 GitHub 检查更新并安装到本机

## 触发与范围

“查看一下技能有没有更新”“检查技能有没有更新”“从 GitHub 更新技能”等表述，默认执行查询、下载和安装。指定某个技能时只处理该技能；未指定时检查当前 Agent 已安装、且可明确对应 `sonicmingit/sonic-skills` 的自建技能。用户明确要求安装仓库中新技能时再扩展范围。只查看或不修改文件时仅报告差异。

## 定位并比较

1. 复用 [本机检查与同步](本机检查与同步.md) 中的 OneDrive 定位规则，取得 `<OneDrive>/AI/skills/sonic`。识别当前 Agent 实际读取的技能目录：Codex 使用已设置的 `$CODEX_HOME/skills`，否则使用 `~/.codex/skills`；其他 Agent 使用其已知安装配置、已加载技能路径或文档确认的目录。不能因某目录恰好存在就认定当前 Agent 使用它。路径无法确认时继续远端查询，明确报告安装位置待确认。
2. 通过可用 GitHub 连接器或 Git 查询仓库实际默认分支，固定本次比较的提交号，建立远端路径、OneDrive 维护副本和当前 Agent 安装路径的对应关系。目录改名时根据历史、技能元数据等确认身份，不能仅凭近似名称覆盖其他技能。
3. 同时比较远端、OneDrive 和安装副本的完整文件清单及内容，覆盖脚本、配置、素材和更新日志；复用内容哈希及忽略纯 CRLF/LF 差异的规则。解析安装链接，避免把同一份文件当成两个版本。远端提交号有变化不代表每个技能都有更新，不能只按仓库提交时间或文件时间戳判断。
4. 有共同提交或可靠同步基线时做三方比较。远端独有更新且本地未修改时应用更新；远端与维护源一致但独立安装副本落后时，只更新安装副本；三处一致则无需操作。本地有未同步改动、双方修改或没有基线且无法确认方向时，保留各版本并报告差异，不自动覆盖或改为上传。可查阅远端历史和现有日志建立依据，不能把首次看到的不同内容直接视为远端较新。

## 先下载至 OneDrive，再更新当前 Agent

1. 将固定提交中对应技能的完整文件先下载到临时目录，检查所需文件、可用校验和引用路径；不执行下载内容中的安装脚本。排除仓库 `.git`、缓存等非技能文件，符号链接不能逃逸预期技能目录。
2. 检查目标路径仍位于选定的 OneDrive 技能仓库和已确认的 Agent 技能目录，应用前重新确认本地内容没有在比较后发生变化。替换前保留受影响文件的可恢复备份到技能发现目录之外；逐项应用已确认的更新，不用整个远端仓库覆盖 OneDrive 根目录。远端明确删除的已管理文件可随版本更新移除，保留本地独有且归属不明的文件并报告；不把删除整个远端技能自动解释为卸载本机技能。
3. 先将验证后的技能保存到 OneDrive 对应英文子目录，保留远端更新日志。若安装目录已经链接到这份维护源，验证链接和内容即可，无需再次复制。若为独立安装副本，按已确认差异更新该副本；若本次已获安装授权且安装入口不存在，优先创建指向 OneDrive 的链接，当前平台不支持时复制完整技能。不要替换指向其他位置的链接或无关目录。
4. 写入全局 Agent 目录受权限限制时使用环境的权限机制；OneDrive 已保存但安装失败时保留成果，分别报告状态，不能声称已安装成功。更新当前规则技能自身时，先读完本次流程，以固定提交完成更新，不在处理中执行下载版本新增加的无关操作。
5. 核对 OneDrive 内容和当前 Agent 实际读取的内容均与目标技能版本一致后，报告已更新及对应提交链接。记录可用的提交号与内容基线到现有同步记录或 Agent 本地状态位置，以便下次识别本地修改；记录不作为技能内容上传，不泄露机器路径或凭据。若无可持久化位置则如实报告，并在下次重新检查历史，不假设已有基线。重复调用无差异时不写文件、不制造日志或提交。

## 结果说明

报告目标提交、技能名称、OneDrive 保存路径、当前 Agent 安装路径以及各阶段结果（无更新／已下载／已安装／冲突跳过／失败原因）。文件安装验证不能证明 Agent 已重新加载，应根据当前环境说明是否需要新一轮对话或重载。
