# SD2 分支与刷写

## 按分支选择镜像

先认板，再找同一版本发布说明、文件名、字节数和 SHA-256。以下地址是字节偏移。

| 板型 / 分支 | 镜像和地址 | 刷前核对 |
|---|---|---|
| 主版原厂 V1.4 | `SmallDesktopDisplay_V1.4.bin`，配套资料通常从 `0x000000` 写入 | 核对同版教程。原厂 Arduino 的 4M2M 分区只用于对应工程 |
| Oray / 掌控 | 配套的 4 MB `Oray.bin`，按其整片镜像说明从起始地址写入 | 会覆盖镜像覆盖范围内的配置和数据，即使没有选择擦除 |
| 主版飞鱼 | 同套 `firmware.bin` → `0x000000`，`littlefs.bin` → `0x100000` | 使用支持多段写入的 ESP8266 工具逐行核对两个地址。缺图先检查配套文件系统 |
| 梦秋 | `2.9.8Fang.bin` | 使用该版本的烧录说明，地址未知时停止 |
| SD mini | 仅 1.33 英寸分支的配套镜像 | 独立核对板型、布局和下载工具 |
| BTC / HA / TeslaMate | 对应工程的发布应用 BIN → `0x00000` | 现有发行采用 DIO、40 MHz、4 MB。LittleFS 用于运行时配置，无需飞鱼文件系统 |
| AI / Bridge | 对应发行包的固件 → `0x00000` | 核对 MANIFEST 的 DIO / 40 MHz / 4 MB 和对应 Bridge。先退出占用串口的桌面客户端 |

Windows 先识别新出现的 COM 口，关闭监视器和 Bridge。保留现有配置作为默认选择；跨固件、跨布局或使用整片镜像时先备份原 Flash/配置，并备好对应回滚包。只有在用户明确要求写入目标设备时才执行刷写；清空整片 Flash 另行确认。下载失败先看启动脚和复位时序，按板上配套教程进入下载模式。写入成功后恢复正常启动电平、复位，检查串口版本、Flash 容量、设置加载结果和屏幕。

工作区的网页刷机工具通过 Chrome/Edge 打开本机 HTTP 服务，内置镜像仅由 `bin/manifest.json` 列出，每次操作写一个选定文件。上传的本地 BIN 只用于本次会话。双镜像优先使用能一次列出两个地址的工具。
