# SD2 开发与排错

## 两条开发路线

- **复现原厂。** 从厂商源码压缩包中取出 V1.3.4 或 V1.4，在单独工程中打开 `SmallDesktopDisplay.ino`。按原包复现 ESP8266 Arduino Core 2.6.3、NodeMCU 1.0、4 MB / 2 MB FS、随包 libraries 和 TFT_eSPI 的 `User_Setup.h`。先编译原版再动驱动或库。V1.3.4 含 Wi-Fi 休眠，V1.4 的常驻 Web 服务对应不同功耗行为。
- **新建信息屏。** 只读实体或数据看板可从 HA 工程的显示、配置存储及网络失败缓存入手；需要共享像素布局时参考 TeslaMate，桌面桥接才选 AI。建立独立的 `sd2-<功能>` 工程，沿用选定基线的屏驱动、引脚、依赖版本和文件系统，剥离原有业务接口、用户配置和凭据。BTC / HA / TeslaMate 配置为 Arduino、`esp12e`、`espressif8266@4.2.1`，AI 采用 `nodemcuv2` 和不同依赖，上传前改用实际枚举的串口。
- **编译和发布。** 从选定工程的 firmware 目录运行 `platformio run -e <环境名>`，检查 RAM、Flash、链接错误和 `.pio/build/<环境名>/firmware.bin`。在发布清单记录板型、版本、源码基线、依赖、构建日期、每段镜像的大小/地址/SHA-256 和回滚包。PowerShell 用 `Get-FileHash -Algorithm SHA256 -LiteralPath <文件>` 复核。未有可复现的产物前，先排查依赖和构建环境。
- **设备行为。** 配置用当前工程的文件系统；变更结构要能读取旧配置，必要时说明迁移。网络调用设超时、限制 JSON 内存，失败时保留上次有效值并标出陈旧。屏幕按 240×240 规划，周期计时局部重绘，状态切换再全屏刷新。凭据不进入串口、网页回显或发布包。
- **验收。** 分开记录编译、模拟器、刷写、实机运行与服务联调。实机检查冷启动、断电后配置、刷新和网络失败恢复，留存版本、脱敏日志与画面。只有实际观察过的项目和版本才能标为实机通过。

## 从现象定位

| 现象 | 先查什么 | 修复后如何确认 |
|---|---|---|
| 无 COM 或串口被占 | 数据线、设备管理器识别的 CH340/CH343、监视器和 Bridge 进程 | 端口随插拔出现或消失，关闭占用后可独占打开 |
| 循环启动或不能下载 | 区分 ROM 启动输出和应用日志；查 3.3 V、GPIO0/2/15、Flash 配置和该分支布局 | 恢复正常启动电平，断电再上电，版本/配置日志稳定 |
| 编译通过、黑屏 | 先看串口是否进入应用，再查屏供电、GPIO5 背光和极性，最后比对 CS/DC/RST、ST7789 配置与 SPI 时钟 | 固定亮度画红绿蓝色块，再测亮度变化和冷启动；记录实机画面 |
| 颜色或方向异常 | RGB/BGR、反色选项、旋转和窗口偏移，逐项对照同板已知配置 | 色块、四角标记和文字朝向都正确 |
| 更新时闪屏 | 检查周期任务是否每秒清全屏，分开状态切换和文本局部重绘 | 连续观察数个更新周期，再切换场景 |
| 中文缺字、链接失败或堆不足 | 核对字符覆盖、字模格式、RAM/Flash 与运行时堆。TeslaMate 用精简字集；HA 0.1.2 已编译完整 GB2312 字库 | 用目标文本测试缺字、截断和最坏内存；编译数字与实机结果分别记录 |
| 飞鱼缺图或配置异常 | 检查同版双镜像及各自偏移；对照原布局，先备份再修复 | 冷启动后资源可见、配置可读、重启后仍保存 |

| sd2-btc-display | `firmware` | `btc_sd2` |
