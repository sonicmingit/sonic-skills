# sonic-SD2开发指南

用于 SD two / SD2 桌面小电视的认板、固件开发、刷机诊断和项目整理。先确认屏幕尺寸、目标分支、当前操作以及现有依据。只有 1.33 英寸时转查 SD mini 配套资料，地址或板型未确认时先完成识别。

- 查询接线、供电、复位、屏幕或背光时，查 [硬件基线](references/硬件基线.md)。区分项目构建参数、原厂配置与实机观察。
- 新建信息屏时，先选已有工程做基线，按 [开发与排错](references/开发与排错.md) 编译最小画面，再接入网络数据、配置和刷新。黑屏从启动日志和背光开始排查。
- SD2 固件创建配网热点时，统一使用默认热点密码 `12345678`，首次配网和断线后重新开启热点都采用同一默认值。设备连接家庭或办公 Wi-Fi 时仍使用用户配置的密码。 核对固件启动热点的各个入口、设备配网提示和 README 的连接说明。
- 选择 BIN、备份或恢复时，查 [分支与刷写](references/分支与刷写.md)。先列板型、应用/文件系统/整片镜像、版本、偏移与哈希；仅提供指南或诊断时不操作硬件。
- 从第一张可用界面或设计稿起，在每个项目根目录维护一张能说明核心用途的当前预览，固定名为“项目预览.png”（实机照片可用“项目预览.jpg”）。README 开头用相对路径嵌入图片，并写清来源（实机、模拟器或设计稿）与对应版本或设计阶段。每次界面或设计变更都在同一批改动中替换预览并核对 README 显示；只有内部逻辑变动时复核现图仍能代表项目即可。根目录只留一份当前预览，历史证据留在项目资料中。
- 归档时，基础资料、共享开发资料、全部项目、共用工具、文档依次放入 `01_基础资料` 至 `05_文档`（分别为 `02_开发资料`、`03_开发项目`、`04_工具`）。所有项目共用 `03_开发项目/sd2-<功能>`，功能名为小写英文、数字与连字符。专属脚本、发布包和证据跟随项目；原厂资料整包保存。
- 新单镜像命名 `<项目名>-v<版本>.bin`；多段镜像增加 `-app`、`-littlefs` 或 `-full` 后缀，各段独立记录偏移、大小和 SHA-256。实测文档用 `YYYY-MM-DD-项目名-验证主题.md`。历史发行保留原件，索引和工程首页分开写当前进度、具体版本、验证范围与待办。
- 有工作区时，从其 README、项目索引和目标工程的 platformio.ini、发行清单与踩坑记录取证；在其他目录中以用户给出的实物与配置为准。交付时列清构建结果、设备验证范围以及尚待实机的项目。
