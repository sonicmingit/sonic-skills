# 项目规则

## 项目与技术
- 项目用途：按 README 和代码核实。
- 技术栈与目录：只记录实际存在的结构。
- 开发/检查命令：从项目文档和配置核实，注明未运行项。

## 修改边界
- 沿用已有风格，不覆盖未知来源改动，不顺便重构无关模块。
- 不将凭据、私有日志或无关个人信息写入项目文档。
- 提交、推送、发布、部署与破坏性操作遵守用户授权及当前确认要求。

## 项目交接流程
- 开始工作先读适用规则、当前计划和交接卡，并核对现场。
- 复杂需求先规划，简单修改直接实施并验证。
- 每个可验证小阶段、阻塞或暂停时更新交接卡。
- 明确区分已实现、已测试、已部署和未验证。
- 收尾简要汇报结果、验证与剩余事项。
- 当前计划路径：按项目实际填写；简单任务可无独立计划。
- 当前交接路径：按项目实际填写。
