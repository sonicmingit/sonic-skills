# 子 Agent 模型与思考等级选择

## 默认策略

主模型继续承担设计、调度和整合，不因使用 Astra 设计就把执行任务全部分给 Astra。先判断是否值得委派，再为每个任务分别选择能胜任的较经济模型和思考等级。确定性重复操作优先用现有脚本或工具批量完成，需要语言判断时再交给 Luna。此策略不改变用户选定的主模型。

以下分配是 Sonic 的成本优先起点，不是质量保证或固定价格排名。模型适配、推理档位和工具可用性每次以当前宿主为准。Sol 与 Terra 按任务类型选择，不假设两者存在统一的能力或价格高低顺序。

## 任务到模型的分配表

| 任务 | 优先模型 | 起始思考等级 | 何时改选 |
| --- | --- | --- | --- |
| 按确定规则整理文本、提取字段、分类、重复小改动 | Luna `gpt-6-luna` | `low` | 有多项约束需要推断时考虑 `medium`，复杂语义改写转 Sol 或 Terra |
| 边界明确的局部代码修复、截图核对、界面操作、自然文字整理 | Terra `gpt-6.1-terra` | `low` 或 `medium` | 代码跨模块或需复杂技术推理时优先 Sol |
| 按已定接口实现功能、编写有意义的测试、常规调试和代码审查 | Sol `gpt-6.1-sol` | `medium` | 极简单且可可靠验收时先考虑 Luna / Terra，复杂诊断才考虑 `high` |
| 多约束实现、跨模块故障定位、复杂回归分析 | Sol `gpt-6.1-sol` | `high` | 明确存在能力缺口时评估提高思考等级或请求 Astra，不先默认 Astra |
| 架构取舍、证据冲突且高风险的根因分析、关键设计复核 | 优先由当前主模型承担，必要时 Astra `gpt-6-astra` | 委派时按难度选 `medium` 或 `high` | 新建 Astra 子 Agent 必须说明 Sol / Terra 不适合的具体原因 |

“优先”不要求先让低能力模型失败。若已知上下文、工具、任务风险或推理要求不适合低档模型，直接选择合适档位并写理由。普通验收按被审任务风险选 Sol 或 Terra，不自动再开一个 Astra。

## 思考等级单独选择

- `low` 用于步骤清楚、歧义少、有直接检查方法的任务。
- `medium` 用于多步骤实现、需要有限判断的调试和常规审查。
- `high` 用于跨文件关系、困难定位或多约束推理，写清额外难点。
- `xhigh`、`max`、`ultra` 不作为批量默认。只有具体困难和收益依据充分，且当前工具明确支持时才选。
- 不机械地逐档试满，也不把 Luna 高思考等级视为必然等价于 Sol。比较完成任务的总耗时、返工和验证成本。
- API 支持的档位不等于当前 Agent 工具支持。当前工具若未提供 `none` 或 `minimal`，不得照抄 API 参数。宿主不支持某档位时重新选择有效组合并说明，禁止静默替换成最高档。

## 派发前的强制检查

1. 在计划或简短进度中列出每项任务的模型、思考等级及一句选择理由。每项都应考虑是否可交给 Luna、Sol 或 Terra，不能仅因“主模型正在使用 Astra”而继承。
2. 核对工具中的可用模型 ID、思考等级、上下文继承和模型覆盖限制。上表 ID 不可用时查询当前模型列表，不猜别名，也不自动回退到 Astra。
3. 工具支持时显式传入 `model` 和 `reasoning_effort`，文字提示“你使用 Luna”不能替代模型参数。主模型或子 Agent 的现有推理档位不应成为其他任务的默认档位。
4. 对当前 Codex `collaboration.spawn_agent`，核验工具声明后使用 `fork_turns="none"` 配合模型与思考等级覆盖。当前声明中 `fork_turns="all"` 或省略该字段会继承主模型且不允许覆盖。宿主以后改变参数时遵从新声明，不把此示例用于不同工具。
5. 不继承聊天时，任务消息必须自包含，提供目标、项目目录、适用规则路径、必要背景、已定接口、写入范围、验收条件、禁止再派生代理和回报要求。不要为了换模型丢失关键约束。
6. 分别记录请求参数和宿主可核验的执行信息。工具未返回实际型号时注明“已请求某模型，实际型号未返回”，不得宣称已独立验证后端模型或节省了具体额度。

当前工具格式示例，仅在核对工具声明后使用。

```json
{
  "task_name": "scoped_fix",
  "fork_turns": "none",
  "model": "gpt-6.1-terra",
  "reasoning_effort": "medium",
  "message": "这里填写完整任务卡，包含目录、规则、背景、修改边界、验收方式和禁止再派生代理的要求。"
}
```

如果工具不允许独立选模，明确告诉用户当前无法落实成本分工，不批量创建继承 Astra 的子 Agent 冒充降本。可由主模型完成小任务或提出可行替代，尊重用户要求再继续。全部任务确实都需要强模型时逐项说明，不为满足模型配比硬拆任务。全任务树仍最多并发 3 个子 Agent。

## 失败与升级通知

先区分缺上下文、环境/权限、任务边界和模型能力问题。补齐输入或修复环境不会自动触发模型升级。对同一问题最多做一次有针对性的同配置补充尝试，仍失败则停止重复消耗，评估重新拆分、提高思考等级、改用更适配模型或主模型接管。

升级前向用户简短说明失败证据、当前模型/档位、建议目标及理由，不静默升到 Astra 或高思考档位。用户已授权自动升级时在该范围内继续，否则询问是否采用建议，只暂停受影响任务，其余独立任务继续。已经确定能力不匹配时无须为了满足重试次数再试一次。用户同意的升级范围记录在计划里，不重复询问相同授权。

可用通知格式：“T2 在 Luna low 下仍无法满足某验收条件，已补充某输入。建议转 Sol medium，因为需要跨模块推理。是否按此升级？”不要报告无法核实的金额或额度预测。

## 依据与维护

核验日期为 2026-11-14。以下官方定位与上述 Sonic 执行策略分开维护。

- [官方选模指南](https://developers.openai.com/api/docs/guides/model-selection) 将 Luna 定位于高效率的明确任务，将 Sol 定位于兼顾时间成本的复杂工作，将 Terra 用于视觉/电脑操作、写作及限定代码修复，将 Astra 用于最困难的分析和交付。
- [GPT-6 使用指南](https://developers.openai.com/api/docs/guides/latest-model) 提供当前模型系列与兼容性说明。
- [推理模型说明](https://developers.openai.com/api/docs/guides/reasoning) 说明思考等级影响思考投入，支持值依赖具体模型，不能假定所有产品设置一致。
- 当前 Agent 工具声明是模型 ID、覆盖参数和可用档位的执行依据。上面的任务分配与起始档位是本技能的策略建议，不是官方针对本仓库的性能实测。

新模型出现、ID 不可用、官方定位变化或用户要求重新比较时，查询官方资料并更新本表及更新日志。日常派发先核对宿主能力，资料仍适用时不为每个子任务重复联网。不要把 API 标价直接当成 Codex 订阅额度消耗。
