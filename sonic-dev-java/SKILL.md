# sonic-dev-Java开发规范

调用示例：“使用 $sonic-dev-Java开发规范 开发这个接口，完成后提醒我是否需要 Code Review。”

## 基线与接手

以本技能随附的《Java 开发手册》黄山版（2022-02-03）为固定基线，2026-11-17 核对官方仓库版本。日常开发只读取本地 [PDF 原版](references/alibaba/manual.pdf) 或 [带 PDF 页码的全文](references/alibaba/manual.txt)，不联网查询阿里规范。只有用户要求更新手册时才下载新版本。文本提取可能出现断行，歧义以 PDF 为准。来源、许可证和检索方法见 [资料说明](references/sources.md)。

先读项目规则、构建文件和现有代码，确认 JDK、Spring Boot/Cloud、Maven/Gradle、MyBatis/JPA、数据库及测试框架。全部按项目决定，不设置统一版本或强制选型；沿用 Wrapper、BOM、锁定依赖与 CI，禁止借规范任务自动升级或替换技术栈。无现有约定的新项目按需求提出选择，待明确后采用。

## 阿里重点规则：严格执行

以下为本地手册的归纳，不替代原文。章节名称可在全文中搜索；除特别说明外均来自原文【强制】项。只约束本次新增、修改及受影响代码，不顺带重构全仓。其他规则按任务主题阅读本地原文，保留【强制】【推荐】【参考】等级。发生用户要求或项目兼容冲突时明确说明差异，不能默默绕过。

- **命名与常量**（命名风格、常量定义）：类用 UpperCamelCase，方法和变量用 lowerCamelCase，常量用全大写下划线；禁止拼音与英文混用、不规范缩写、直接散落魔法值。遵循手册中的特殊类型命名约定。
- **对象契约**（OOP 规约、集合处理）：重写方法标记 `@Override`；重写 `equals` 时同时实现 `hashCode`，自定义 Map 键与 Set 元素遵守相等性契约；包装类型比较值不用 `==`，拆箱前处理可能的 null。
- **数值精度**（OOP 规约）：金额和精确小数运算避免二进制浮点误差；不得用 `new BigDecimal(double)` 表达精确输入，使用字符串或 `valueOf`；数值等值比较用 `compareTo`，明确精度和舍入策略（后者为本技能补充）。
- **集合边界**（集合处理）：不在 foreach 中直接调用集合的 remove/add；需要删除时使用正确的迭代方式。明确 `Arrays.asList`、`subList` 等视图的修改限制与相互影响，不作不安全类型转换。
- **并发资源**（并发处理）：普通平台线程池不使用 `Executors` 隐藏无界队列或线程上限；显式配置容量、线程数、命名与拒绝策略。框架托管池核查等价配置；虚拟线程等新版机制按项目 JDK 另行判断并限制下游并发，不机械套用旧模型。自定义 `ThreadLocal` 使用后清理，多资源加锁保持顺序一致，不共享不安全的日期格式化器。
- **异常与资源**（异常处理）：不捕获后忽略异常，不用异常代替正常分支；资源可靠关闭，`finally` 内禁止 return。异常上下文与堆栈按项目日志规范保留，避免泄露敏感信息。
- **数据库与持久化**（SQL 语句、ORM 映射）：参数绑定防注入；使用 MyBatis 时数据参数用 `#{}`，不能把不可信输入拼入 `${}`；动态标识符通过白名单处理。查询明确列，不用 `SELECT *`；更新和删除明确条件，事务行为与业务一致。仅在项目采用对应技术时应用技术专属规则。
- **安全边界**（安全规约）：服务端验证权限及资源归属，输入做有效性校验；日志与展示脱敏，用户输入不能直接进入 SQL、命令或其他执行上下文。

## 中文注释

新增与修改的人工注释必须使用简体中文（本技能将阿里推荐升级为强制）。类、属性、方法的文档注释使用 Javadoc；抽象方法及接口方法说明功能、参数、返回值、异常与实现约束，每个枚举项说明用途。方法内单行注释独立置于语句上方。类、接口、公共方法的 Javadoc 说明职责、参数含义、返回值、异常与重要约束；解释复杂算法、事务边界、并发、幂等及业务取舍。修改行为时同步更新注释。
注释量按职责覆盖和可理解性验收。已核对“注释规约”第 1—12 条（PDF 第 23—24 页），未规定统一注释百分比，不设置凑数比例。简单访问器可依赖明确命名与已有生成工具，避免为了数量重复描述语句。
代码、注释、文件头和业务日志不得写入 Agent 名称、模型名称、AI 生成标记或虚构作者。已有版权与许可证声明依法保留。阿里要求类记录创建者与创建日期；只填写已确认的真实作者和真实日期，无法确认作者时省略作者字段并说明此例外，禁止使用模型或 Agent 名称代填。

## Spring 项目组织

Spring Boot 官方允许多种布局。默认采用按业务领域分包，领域内按职责组织 controller、service、repository/mapper、dto、config；已有合理结构优先沿用。启动类放在业务根包，避免默认包和过宽扫描。使用构造器注入，显式管理配置，禁止循环依赖。
Controller 处理协议、校验和响应，Service 承载业务及事务边界，Repository/Mapper 处理持久化；DTO 与持久化实体按边界分离。简单项目按实际职责设层，避免空壳接口或机械的一对一转发。
Spring Cloud 按业务边界拆服务，通过明确 API/事件契约通信；禁止跨服务直接修改对方数据库。对远程调用设置超时，按业务配置熔断与有限重试，重试写操作必须保证幂等。跨服务一致性按业务选择补偿、消息或事务方案，并覆盖部分失败与重复投递。

## 方法复用

实现前搜索已有方法、服务、转换器和框架能力，并检查调用者及行为契约。
出现可复用的相同业务能力时必须提取到职责所属组件，现有调用统一复用，避免重复校验、计算、转换和查询逻辑。先比较输入、异常、副作用、权限与事务语义，再合并。
仅表面相似但业务规则不同的代码应保留边界。公共组件应有稳定职责，避免把不同领域耦合进万能工具类。跨服务复用通过稳定契约或合适的基础库实现，避免共享业务实体导致发布耦合。
提取后核对全部调用路径、历史数据、空值、异常以及并发行为。

## 必备工程约定

- 接口明确参数校验、错误码、分页上限、权限和兼容策略；统一异常映射，记录可定位的上下文，避免吞异常及重复打印堆栈。
- 事务覆盖完整业务不变量，核对代理调用、自调用、回滚规则及异步边界；外部调用避免长时间占用数据库事务。
- 金额使用明确精度与舍入规则；时间明确时区；集合与可变共享状态注意线程安全；线程池设定容量和拒绝策略。
- SQL 使用参数化，检查索引、N+1 和大批量操作；结构变更使用版本化迁移并说明兼容和恢复方案。
- 凭据通过环境变量或项目配置系统注入；日志脱敏，权限在服务端校验，防止越权、注入及敏感数据泄露。
- 测试覆盖本次业务正常、边界、失败及涉及的并发/幂等路径。按变更风险选择单元、集成和契约测试，复用现有测试设施。
- 构建、格式、静态分析和依赖检查沿用项目 CI。按需采用 Checkstyle、PMD/P3C、SpotBugs 等工具，验证与当前 JDK 的兼容性；工具通过不能代替业务审查。

## Code Review：确认后执行

正常开发执行必要的编译、测试和静态检查，不自动启动独立 Code Review，也不自动调用审查模型或审查技能。完成当前开发后，只提醒一次：“开发及必要验证已完成，是否需要执行 Code Review？”用户回答需要后，读取并执行内置 [Code Review 流程](references/review.md)。用户在当前请求中已明确要求审查，视为本次已确认，不重复询问。沉默、仅调用本开发技能、过去其他任务的同意均不视为确认。

内置流程独立可用，无需安装第三方技能。此次创建或维护技能不等于要求审查业务代码。未获确认时交付实现结果、已执行检查、验证缺口，并注明“Code Review 未执行”。
