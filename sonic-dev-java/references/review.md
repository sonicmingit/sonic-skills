# Code Review 规范

先明确用户目标、基线提交、变更范围和验收条件，读取完整相关方法及调用者，检查兼容性、业务不变量与失败路径。

必查项包括中文注释、重复功能与复用位置、Spring 分层及依赖、事务与线程安全、权限与输入校验、数据库迁移、接口兼容、资源释放、超时重试、幂等、日志脱敏和测试有效性。

每条问题给出严重级别、文件及行号、具体触发条件、用户影响和可执行修复建议。按阻塞发布、应尽快修复、一般改进排序。没有证据的问题标为待核验，纯个人风格偏好不作为缺陷。未执行的测试明确说明。

选择当前宿主实际提供的模型。小范围局部改动使用能够读懂调用链的轻量模型；跨模块业务与事务使用通用高能力代码模型；并发、安全、分布式一致性和复杂迁移使用更强推理能力模型。优先独立上下文评审，工具不支持独立评审时进行主模型复核并如实标记。不得声称切换到不可用模型。审查者默认提出问题，由实现者修复，随后针对受影响范围复查。

审查结束列出已解决问题、剩余问题与验证边界。存在未处理的高风险缺陷时不得声称通过。

可参考 axross/skills 的 code-review 技能，见 sources.md。它是通用差异评审候选，本技能已提供 Java 专用清单。采用第三方技能前检查全部引用、许可证、宿主工具依赖和授权边界，按项目决定安装。尚未对该候选执行真实项目验收。
