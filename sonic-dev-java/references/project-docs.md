# 项目接手与记录流程

## 首次接手现有项目

1. 先读适用的项目规则、构建文件、入口、配置、测试和已有文档，核对真实工作区和代码基线。按模块梳理主要目录、依赖方向和职责，追踪有代表性的请求、任务或消息链路。
2. 在 `01-project-architecture/` 建立架构索引。记录目录层级、各模块已实现功能、源码与测试入口、关键类或方法和已核验的构建、启动与检查命令。使用仓库相对路径和可搜索的代码符号。排除构建产物和缓存，标注覆盖范围，区分代码实现已核实、行为已验证和待核验。
3. 在 `05-agent-records/` 创建 Agent 接手记录，关联架构索引及项目已有规则，记录工作边界、未提交改动、验证证据、遗留问题与第一条可执行的下一步。续接时按下文的任务索引选择记录，再核对项目现场。架构或关键链路变化时更新索引，新建项目在结构明确后建立初版索引。

已有项目规则、计划、设计和交接文档继续作为事实来源。AI 记录引用它们，并补本次任务的内容。JDK、构建工具、框架、ORM、测试或部署命令从项目核实，尚未证实的写为待核验。

## 任务边界与续接

问答、检查和正式 Code Review 保持只读，可读取现有项目记录和检查证据。实际开发或项目、需求、设计分析要保存结论和证据，按任务类型更新相关文档。只分析时保存分析产物，避免生成无内容的设计或实施日志。已经进入开发阶段的工作，即使当前步骤是分析，也把结论写回该任务。

根 README 维护进行中任务索引，至少记录任务编号、主题、分支或工作区、状态，以及对应需求、设计和日志链接。启动或续接时先用用户指定的任务编号匹配，再核对分支、工作区及当前改动。没有编号时按目标与分支定位，只有确实无法判断时才询问。任务完成后更新状态并移出进行中列表，记录文件仍可从历史目录查到。改名后同步更新引用。

## 使用模板

参照 [模板目录](../assets/project-docs/ai-docs/README.md)，在项目根目录建立或复用 `ai-docs/`。保留固定的 `README.md` 作为入口，导航使用生成后的实际路径。模板中的时间、任务编号和待填内容用于说明格式，生成时替换为真实信息，并建立实际任务之间的链接。

| 编号目录 | 生成和维护时机 |
| --- | --- |
| `01-project-architecture/` | 项目初次梳理、目录或关键链路变化时更新 |
| `02-requirements/` | 开发前记录目标、边界、待确认事项和可观察的验收条件 |
| `03-design/` | 实现前说明模块、复用、接口兼容、数据迁移及验证计划 |
| `04-development-logs/` | 实施中按阶段追加时间、实际改动、决策、验证和遗留事项 |
| `05-agent-records/` | 项目分析完成后创建，续接或收尾时按需要更新 |

标注 AI 辅助生成。记录使用北京时间，文件名为 `YYYYMMDD-HHmmss_任务编号_主题.md`，项目级记录可省任务编号，文档内标注时区。固定 `README.md` 是唯一无时间的文件名。小改动使用精简记录，同一任务沿用编号，日志可在同一文件内追加带时间的条目。仅保存脱敏上下文与证据引用。

## AI Talks 的 Git 提交选择

AI Talks 指整个 `ai-docs/`，包括 README、五类记录和 Agent 接手记录。首次需要在 Git 项目写入该目录，且没有已保存或已明确的选择时，问一次：“这个项目的 AI Talks 要全部随项目提交到 Git，还是只保存在本机？”明确选择后按项目保存，后续复用。尚未答复时记为 `pending`，新记录先按本地忽略规则保存，本次提交范围排除 AI Talks。现有跟踪状态等用户明确选择后再调整。后续有明确选择时更新状态，待选择期间不阻塞已授权开发，也不重复询问。非 Git 项目直接本地保存。

在 Git 本地配置中使用 `sonic.aidocsPolicy` 保存仓库根项目的 `commit`、`local` 或 `pending` 状态。独立子项目使用 `sonic-aidocs.<仓库相对子项目路径>.policy`，读取和设置时将完整键作为一个参数。该配置可在同一仓库的后续会话复用；如果更换到新克隆且没有已知选择，再确认一次。用户明确改变选择时，按新状态处理整个目录，并在核对后更新配置。

| 选择 | 执行方式 |
| --- | --- |
| 提交 | 将现有与后续新增、修改、删除的 AI Talks 文档全部纳入该项目的正常提交。撤销为本目录添加的本地排除规则，检查项目的共享忽略规则。已有更广范围的排除规则时保留它，仅针对获准的 AI Talks 文档处理。提交前确认范围并检查脱敏，暂存时只指定该目录。 |
| 仅本地 | 保存文档并添加本地忽略。原先已跟踪的 AI Talks 目录从 Git 索引移除，随下一次 Git 提交记录删除，保留当前本地文档。 |
| 仅本地改为提交 | 撤销此前为该项目添加的排除规则，把现有 AI Talks 文档重新加入 Git 跟踪，后续按提交模式执行。 |
| 提交改为仅本地 | 核对该目录的暂存差异和已跟踪路径。在仓库根目录对其真实相对路径先预演，再用 `git rm -r --cached -- <AI Talks 路径>` 移除 Git 跟踪。保留工作区文件，完成本地忽略并核对结果。仅处理该项目的 AI Talks。 |

本地忽略用 `git rev-parse --git-path info/exclude` 定位排除文件。仓库根项目用 `/ai-docs/`，子项目用对应的仓库相对路径。先用 `git ls-files -- <AI Talks 路径>` 确认仍在跟踪的文件，再用 `git check-ignore -q -- <目录内未跟踪的文档路径>` 验证忽略效果。需要定位匹配规则时使用 `git check-ignore -v`。已跟踪的 README 不能代替未跟踪路径验证。已有暂存冲突时保留用户改动并处理冲突，避免强制覆盖。

切换到仅本地模式影响后续提交中的目录跟踪，旧提交对象仍存在。如果用户明确要清除历史版本，应单独确认需要处理的分支、标签、远端及协作者影响，再执行历史清理。
